## Architecture (Phase 0+1 subset)

```
data/ (static, generated by Claude Code)          runtime
├── synthetic/  500+ discharge records   ┌──────────────────────────────┐
├── golden/     200 w/ answer keys       │ orchestrator (plain Python)  │
├── policies/   clauses w/ stable IDs    │  retries + audit → Postgres  │
└── icd/        ICD-10 table → pgvector  └──┬─────┬──────┬──────┬───────┘
                                            ▼     ▼      ▼      ▼
                                       Summarizer Coder Packager Submitter
                                       (LLM)   (RAG+LLM) (rules+ (simulator,
                                                          fhir)   no LLM)
                                            └──── llm.py: gemini | mock ───┘
```

### LLM provider interface (`src/claimguard/llm.py`)
- `complete(prompt, *, system, tier, json_schema=None)` — tier is `"reasoning"` or `"fast"`, mapped to models in config.
- Providers: `gemini` (google-genai, `GEMINI_API_KEY` from `.env`) and `mock` (deterministic; all tests use it — CI needs no key, spends nothing).
- `embed(texts)` for RAG, same provider split (Gemini free embedding model / hash-based mock).
- Switching to the Claude API later = config change only.

### Data plan
- **Synthetic records** (`data/synthetic/`): generated in scripted batches by Claude Code — clinically varied templates (specialties, stay lengths, cashless/reimbursement, partial approvals, rejections, code-switched Hinglish free text, death-in-hospital) + Faker for demographics/vitals. ≥500 records.
- **Golden set** (`data/golden/`): 200 records with answer keys (correct ICD-10 codes + expected packaging outcome). Source of truth for eval.
- **Policy corpus** (`data/policies/`): 3–4 synthetic insurers × plans; clauses with stable IDs, sub-limits, exclusions, waiting periods; structured JSON + prose. Built now so Phase 2's Negotiator has grounding soil.
- **ICD-10 reference** (`data/icd/`): ~2K common codes (WHO subset), embedded into pgvector.
- **Edge-case generators**: one function per PROJECT_SPEC §9 case, reproducible.
- **`docs/NHCX_ACCESS.md`**: documents that individual live NHCX submission is gated to onboarded orgs → we ship a labeled simulator.

### Database (Postgres 16 + pgvector, Docker Compose)
Tables: `claims`, `audit_log` (replayable, per-claim), `policy_clauses` (+ embedding), `icd_codes` (+ embedding), `handoff_timestamps` (schema now, Radar consumes it in Phase 3). Consent/erasure interface stubs (DPDP-aware, no-op on synthetic data).

### Pipeline agents (pure functions, LLM injected)
- **Summarizer** (reasoning tier): record → structured discharge summary; no invented facts, cites source fields.
- **Coder** (fast tier + RAG): summary → ICD-10 codes with confidence; retrieval over pgvector; low-confidence → `human_review` flag, never silently submitted.
- **Packager** (rules + fhir.resources R4): summary+codes → NHCX-shaped claim; rejects malformed/missing-document claims pre-submission.
- **Submitter** (deterministic, no LLM): simulator; idempotent, retryable, status polling.

### Eval (`python -m claimguard.eval`)
Golden-set runner → coding F1 with hierarchical credit, packaging validity, grounding-rate stub (gate armed in Phase 2). CLI report. Runs zero-score on empty pipeline (Phase 0 exit criterion).

## Exit criteria

**Phase 0** (amended): `docker compose up` → db + api healthy · `python -m claimguard.gen-data` produces ≥500 synthetic + ≥200 golden · `python -m claimguard.eval` prints zero-score report · `docs/NHCX_ACCESS.md` exists.

**Phase 1** (unchanged from PROJECT_SPEC): record flows to valid NHCX-shaped submission fully audited · Packager rejects malformed claims pre-submission · low-confidence codes flagged · coding accuracy reported with hierarchical credit.

## Execution: subagent waves (ponytail rules apply to all)

| Wave | Agents (parallel within wave) | Gate |
|---|---|---|
| 1 | **A** scaffold+compose+DB+config+llm.py · **B** data engine/loaders (Claude Code generates content) · **C** eval harness skeleton | Phase 0 exit tests green |
| 2 | **D** Summarizer + Coder · **E** Packager + Submitter | unit tests green |
| 3 | orchestrator + integration + edge-case tests (§9: 1, 5, 6) | Phase 1 exit tests green |

Every non-trivial unit lands with one runnable check (pytest). Deliberate shortcuts marked with `ponytail:` comments.

## Out of scope (this effort)
Negotiator (Phase 2) · Compliance Radar UI (Phase 3) · patient comms (Phase 4) · frontend app · LangGraph · WhatsApp/Twilio · real NHCX access · ambient scribe.
